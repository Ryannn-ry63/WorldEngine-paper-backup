训练和权重导出验收位于 `20260916_prefeedback_factorial_v1`，全部12模型通过。仿真评测是独立run `20260916_factorial_eval_v2`，不修改训练源码或复用旧模型名称。

评测run保存运行时源码快照及逐文件哈希，仅在原观察器的协议白名单增加 `selector_prefeedback_factorial_eval_v1`，另生成同构原生评测配置。源码快照是可审计的运行产物，保存在runs而非复制一套研发分支。所有模型、历史场景和参考结果均校验哈希。

在 `code/` 运行：

```bash
bash run_evaluation.sh prepare
bash run_evaluation.sh preflight
# 已释放GPU时运行首个8场景NR迁移检查

# 如需自动释放/恢复用户占卡，加 --holder-pid 当次核实的PID --pane 0:0.0
```

PID不可复制旧记录；脚本会核对命令、cwd与tmux父进程。每次collection结束或失败均清理自己启动的进程组，并恢复已释放的占卡。没有传入holder-pid时，调用方自行提供空闲GPU。

目前入口支持导入预检和闭环collection；开环评测与29列新结果导出仍需接入，不能把78个计划条件写成78个已支持/完成条件。完整288和common64均为已有实验暴露集合，不是新盲测。

失败的collection保持原样以供诊断，不静默删除或覆盖；检查原因后显式归档再重试。代码或协议变更使用新评测run ID；训练run继续保持原始哈希。

跨硬件不假定动作/指标严格相同。如果4090与旧H100结果未通过既定容差，保存失败差异，先定位数值/环境原因，不放宽阈值宣称迁移成功。预检只做CPU导入/配置解析；不代替CUDA内核或物理仿真验证。
