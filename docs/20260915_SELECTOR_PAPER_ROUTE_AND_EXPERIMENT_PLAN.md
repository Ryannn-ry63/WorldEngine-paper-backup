## 2. 当前模型关系：哪些从头训练，哪些是继续训练

| 名称 | 实际训练方式 | 应回答的问题 |
|---|---|---|
| 预训练 DiffusionDrive | 基础驾驶模型，提供感知、候选生成和原生选择 | 基础性能与原有候选覆盖如何？ |
| 本项目 selector V2 | 冻结感知和生成器，用奖励后训练原生 selector | 改变选择器的训练目标是否有用？ |
| V3 | 冻结完整基础模型，新增 scene-conditioned residual selector；内部参数重新初始化，最终输出层置零 | 新表示与残差参数化是否更适合吸收奖励监督？ |
| P1 / CL_NLL / MID | 从已经训练好的 V3 rarelog 权重继续训练同一个 residual selector，保留 dense GRPO 并加入闭环反馈目标和 teacher KL | 闭环反馈是否带来原有训练没有解决的收益，怎样利用反馈更可靠？ |

**V3 新增 selector 的参数从头训练，但初始决策与基础模型一致。当前 P1/MID 继承的是已训练 V3 权重，没有重新初始化 selector，也没有增加一个 V4 网络。** 本项目的“selector V2”还应与外部论文 DiffusionDriveV2 区分。

当前 P1/MID 的起点是 V3 rare-original 实验中的 `rare_tuned / seed0 / epoch64`：

```text
experiments/diffusiondrive/grpo_selector_v3_rare_original_v1/models/rare_tuned/seed0/train/epoch_64_scene_selector.pt
SHA256: aed5e36f1ccb0df96b703a901b54f48c41dcf1967cc86d63519eb4da37519eb2
```

三个优化 seed 使用同一个已训练 V3 起点和 seed0 采集的反馈上下文。每个 seed 具有自己的 shared 闭环训练父节点，后续对照从对应父节点恢复模型、优化器和 RNG，再继续训练。共同父节点已经接受过闭环反馈。

因此，当前三 seed 衡量的是固定初始化与反馈数据条件下的优化波动，不能写成完整训练和反馈采集流程的三次独立重复。

## 3. 论文主旨如何从 V3 延伸到 P1/MID

### 3.1 主旨确实扩展了，后训练范式保持一致

用户关心的核心问题是：原来用一个 GRPO 损失就能训练 V3，后来增加 P1 的 Pair/NLL，是否已经改变论文主题？

本轮结论：**主题由“用 GRPO 后训练 selector 有效”，扩展为“如何用奖励与有限闭环反馈改善冻结生成器上的选择策略”。如果最终方法采用 P1/MID，就不能再用“只使用一个 GRPO 损失”描述整个方法。**

三个层次需要分开：

| 层次 | 含义 | 在当前路线中的位置 |
|---|---|---|
| 后训练 | 在已有基础策略之上继续学习 | 始终是研究范式 |
| GRPO / Pair / NLL | 把反馈转成参数更新的优化方式 | V3 使用组内相对奖励优化；P1/MID 扩展训练目标 |
| 局部候选奖励 / 闭环分支回报 | 监督信息从哪里来 | 后续方法增加了模拟器中的执行反馈 |

最初 `beta=0` 的 V3 确实仅用组内相对奖励损失训练新增 head。实现枚举完整 20 个动作并优化期望优势，正式论文应准确称为 full-action group-relative policy optimization，避免声称严格复现带采样和 clipping 的标准 GRPO。后来的 rarelog 初始化版本还要单独记录其 KL 等配置，不能将不同 V3 配方混为一谈。

### 3.2 V3：建立奖励驱动的选择能力

基础假设是：在部分场景中，高质量候选已经存在，原 selector 没有稳定选中。V3 用同一候选集的稠密局部奖励训练 residual selector，研究冻结生成器后还能获得多少选择收益。

V3 的价值独立存在。P1 后续有收益不意味着 V3 无效，也不意味着原先“一个损失”的结果不值得保留。需要用候选覆盖、oracle regret 和公平结构消融证明 V3 的作用，不能仅凭 V2 与 V3 的分数差断言表示瓶颈。

### 3.3 P1：研究局部候选评价到连续驾驶之间的缺口

合理的下一步问题是：选择局部高分候选之后，连续执行和重规划是否同样获得收益？执行会改变后续状态、候选和交通交互，局部评分与闭环结果可能存在不一致。

这是引入闭环反馈的研究动机，尚不能直接写成已被完整证明的失效机制。局部代理与闭环分支的差别也不止 horizon，不能把现有比较称为只隔离了“短期/长期奖励”。闭环回报来自当前模拟器和给定续接策略，不是真实世界、对任意后续策略都成立的 Q 值。

当前目标的概念形式是：

```text
L = L_dense_GRPO + L_closed_winner_NLL + lambda * L_closed_Pair + beta * L_teacher_KL
```

精确 gap 权重、采样与归一化沿用对应冻结实验契约；上式用于解释方法，不替代实现定义。

- dense GRPO 保留完整候选集上的稠密奖励训练。
- Pair 学习已比较候选之间的相对优劣。
- winner NLL 提高获胜候选在全部 20 个候选中的概率，尝试将局部偏好变化转成实际选择变化。
- teacher KL 约束策略偏移，但其存在本身不保证安全或能力不退化。

NLL 在形式上属于监督学习损失，但目标来自闭环分支比较的获胜候选，而非原始人工示范轨迹。整套方法仍由驾驶表现驱动，同时包含奖励优化和奖励产生的偏好监督。

必须保留一个边界：**两个候选之间获胜，不等于优于全部 20 个候选；未知候选不能被当成已知坏候选。** P1 的局部比较与全局选择之间的关系需要验证。

### 3.4 MID：研究反馈内部的权重与能力保持

当前 CL_NLL、MID、P1 分别使用 `lambda=0 / 0.5 / 1`，其他既定训练项与数据采样不变。新敏感性实验检验 `0.4 / 0.6`。

**MID 调的是额外 Pair 损失权重，不是 common/rare 数据采样比例，也不是简单将 GRPO 与闭环反馈整体按比例混合。** CL_NLL 仍然包含 winner NLL，本身不是没有闭环监督。

P1 → MID 可以作为统一方法内部的权重选择和稳健性研究。开发集上的出发点是：P1 的 rare 较好，较弱 Pair 方案的 common 较好，MID 可能保留前者收益并改善后者。正式结果还需验证这种权衡是否稳定，不能先把“P1 天生偏 rare、伤 common”当成结论。

### 3.5 新增关键对照：同样闭环反馈能否继续使用 GRPO

**GRPO 并非只能使用局部奖励。原 V3 的反馈局限，不能被表述成 GRPO 算法必然不能处理闭环。**

后续补实验必须加入：在同一初始化、相同闭环反馈、相同训练预算下，比较组内相对奖励更新与 Pair/NLL 训练方式。只使用实际查询到的回报，不为未查询候选补造奖励；归一化、参考策略和可比较动作集合需在实验前冻结。

这项实验分离两个问题：

1. 收益是否主要来自新增闭环信息？
2. 在这些信息相同的条件下，P1 的训练目标是否有额外价值？

如果较简单的闭环奖励优化已经足够好，就考虑保留更简洁的方法；如果 P1 更好，才据此解释额外目标的必要性。Pair/NLL 的组合本身不直接构成新颖性。

### 3.6 暂定的论文组织方式

推荐主旨：**冻结扩散生成器上的奖励驱动 selector 后训练：利用稠密候选奖励建立选择能力，研究有限闭环反馈如何进一步改善连续驾驶决策。**

最终呈现统一方法及其消融，不按 V2 → V3 → P1 → MID 的研发时间顺序堆贡献。V3 可成为 dense-only 基础方法，闭环学习是待证明价值的扩展，MID 属于内部权重研究。两阶段只有在实验支持其作用时才作为方法设计强调。

**现有 shared 父模型上的 Continue/P0/P1 等消融不能替代 E4。** 父模型已经接受过闭环训练，它们回答的是后半段条件归因，不是整个反馈阶段从无到有的必要性。

结构和损失消融优先集中在一个冻结训练配置；最终主表再补数据横轴与重复。不得挑最佳 seed 作论文主要结论，单 seed 可作为明确标注的个例行。

## 7. common / rarelog / rarerollout 与主表的正确对应

### 7.1 三者首先是训练配置

| 训练组 | 既有语义 | 公平比较要求 |
|---|---|---|
| common | common 数据；历史实验还需区分完整 common 与 paired-common | 明确实际 manifest，不能把不同 common 池视为同一数据集 |
| rarelog | common + 真实 rare 日志样本；既有 rare-original 使用 50/50 采样 | 对应预算一致的 common 对照 |
| rarerollout | common + 真实 rare + 合成 rare rollout | 冻结合成来源与混合比例，控制训练预算 |

当前 P1/MID 采用 V3 rarelog 起点、common/真实 rare/合成 rollout 混合 dense replay 和闭环反馈。它不能被直接写成已完成的三个独立训练组，也不宜仅靠模型名中的 `rare_rollout` 隐去初始化与训练历史。

若要证明训练数据的作用，各组从一致的基础模型和 selector 初始化规则分别训练，后续 dense 与反馈来源也保持组别定义。若故意给三个已有基座使用同一混合反馈，则单独标为“不同初始化上的后训练适用性”，不能替代纯数据消融。

历史 `paired_common` 与 `rare_frozen` 为 4,800 updates，`rare_tuned` 为 19,200 updates。后者可以作 tuned/强基线结果，但不能把额外四倍训练的收益全部归因于 rare 数据。旧结果仅在数据、预算和评测契约满足比较要求时复用。

## 8. 新方法的可能方向与触发证据

### 8.1 有限候选反馈如何影响全局排序

先检查已查询候选的局部纠正，是否在未查询候选上产生不合理的全局排序变化。若证据成立，可研究限制候选概率转移范围、保留未查询候选相对排序的更新方式。

这需要区别于已有 P0、teacher KL 和完整局部监督，也要超过简单强基线。不能把 Pair/KL 换名当成新方法，更不能默认未知候选都比获胜候选差。已有 P2/P3 候选补查结果需一起复核，不自动重复查询方案。

### 8.2 局部改善到持续部署的收益转化

在物理一致的首次决策分叉处，区分反馈覆盖不足、续接策略变化和可用观察信息不足。只有诊断支持对应原因时，才选择一次针对性改动：如反馈刷新、监督表示调整或能力保持约束。

反馈刷新要与等模拟预算的静态补标签比较；能力保持改动要与简单约束优化比较。旧验证器/覆盖扩展负结果保留，避免把“更多 common 数据”或“再加一个 gate”无依据地当作解决办法。

### 8.3 候选覆盖不足时允许重新考虑生成器

若关键失败根本没有可行候选，就缩小“选择瓶颈”结论的适用范围，并考虑生成器改进。不能为了保留现有代码或已有结果，预先断言生成能力已经足够。

### 8.4 与已有工作的区别必须由证据支撑

本轮已核对的近邻工作包括：

- [RAD-2](https://arxiv.org/abs/2604.15308)：包括闭环 RL 训练的轨迹打分器。
- [CRAFT](https://arxiv.org/abs/2605.04470)：包括稠密反事实代理监督、闭环纠正与 teacher regularization。
- [DriveDPO](https://arxiv.org/abs/2509.17940)：包括驾驶策略的偏好优化。
- [CLOVER](https://arxiv.org/abs/2605.15120)：包括候选评分、规划指标监督和保守自蒸馏；其使用“closed-loop”的具体协议需与本项目区分。

因此，“生成与选择分开”“GRPO 加闭环反馈”“增加 Pair/NLL”均不能单独作为已确立的新意。候选约束、反馈预算和自然重规划是研究设定，仍需重要发现、方法收益或效率证据支持贡献。

### 11.3 第一优先级：固定 rarelog 起点，分开数据扩展与反馈

定义 D_L = common + 真实 rare，D_M = common + 真实 rare + 合成 rollout。从同一个、尚未接受 P1/shared 训练的 V3 rarelog checkpoint，做下面的 2×2 对照，无续训 V3 另作基线。

| 实验 | 第二阶段 dense replay | 闭环偏好监督 | 用途 |
|---|---|---|---|
| D1 | D_L | 不加 | 同来源、等预算继续训练 |
| D2 | D_M | 不加 | 无闭环偏好时，数据扩展的作用 |
| D3 | D_L | 加固定反馈 F | 不增加合成 replay 时，反馈的作用 |
| D4 | D_M | 加同一反馈 F | 混合 replay 与反馈结合，当前探索路径的受控版本 |

比较 D3−D1 与 D4−D2 检查反馈的作用；比较 D2−D1 与 D4−D3 检查合成 replay 的作用；差中之差检查交互。只比较 D3 与现有 P1，仍不能分离全部因素。

实施时必须满足：

- 四组直接从原始 V3 出发，覆盖整个后续训练预算；不能把已接受 mixed/闭环训练的 shared 模型当成“无合成/无反馈”起点。
- 固定 dense 总 draw 数、common draw 序列和 common/hard 比例；D_L 用真实 rare 填 hard 槽位，D_M 用固定真实/合成混合填充。报告 unique 数据量和真实 rare 曝光量。这测的是固定预算下的来源替换，不只测合成样本质量。
- D3/D4 使用相同反馈状态、候选、回报、访问/续接策略、权重。D1/D2 不使用闭环偏好标签。teacher KL、用于 KL 的状态范围在四组固定，因此先隔离闭环偏好监督，而非宣称完全不接触反馈状态。
- 另保留原配方 dense-only 续训基线或消融，拆分反馈状态/KL 的作用；局部监督强基线和同反馈 GRPO 对照继续按 E4/E5 执行。
- 首轮归因可用固定已有 F，但要公开来源。若 F 的场景不属于 D_L 允许范围，D3 只能标为“无合成 dense replay + 固定外部反馈”，不能填为严格同来源 rarelog 主表。严格版本需在审核后的 D_L 场景源上采集 F。
- 当前 P1/MID 仅在全部数据、初始化、训练阶段、KL、采样和评测契约匹配时复用为 D4，否则作为参考结果并补受控版本。不能为复用一个结果而混淆对照。

这是第 6 节 E4/E7 的细化。若发现数据扩展本身贡献很大，应把数据课程的作用单独报告；若同来源反馈也稳定有效，则“在已有数据来源上继续改善选择”这条方法主线更清楚。

### 11.4 第二优先级：在 V3 rare_rollout 上补对应来源续训

**建议补，但同时给配对基线。** 最小组合为 V3 rare_rollout 原模型、等预算 dense-only 续训、使用最终冻结反馈方法的续训。Dense 数据配置在这一组内部一致。

这回答：基座已经见过合成 rollout 后，闭环反馈是否仍有额外增益？可以检验收益是否依赖 rarelog 基座第一次接触合成 replay 这一特殊路径。

选普通 scalar V3 rare_rollout 作为对应基座；gate-conditioned 同时改变目标，作为独立强基线。rare_tuned 的阶段 A 为 4× 训练预算，不能与预算不同的 rollout 起点直接作数据因果比较。先比较各自起点下的配对增量，正式数据消融再统一阶段 A 预算。

反馈也需要明确两种实验问题：

- 复用原 V3 rarelog 采集的 F，换成 V3 rollout 起点：只测试固定离线反馈在不同初始化上的适用性，公开行为/续接策略，不能称为新模型自己的反馈。
- 验证完整后训练流程：按同一采集规则和预算，从 V3 rollout 对应场景源获取其访问状态与反馈；同组方法对照共享固定采集数据，完整流程重复再用独立采集 seed。不能把旧反馈当成新策略同状态、同续接下的回报。

先完成 rarelog 归因，再冻结方法做 rollout 扩展；暂不展开所有初始化 × 所有 replay × 所有 loss 的全组合。
